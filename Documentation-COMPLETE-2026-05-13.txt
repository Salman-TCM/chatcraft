Call Data & Webhooks
Call data is automatically captured and stored:
ElevenLabs Post-Call Webhook:
After each call ends, ElevenLabs sends call transcript and summary to your system. This data appears in the contact's conversation history in your Inbox.
Contact Creation:
When someone calls, a contact is automatically created (or matched to existing contact) based on their phone number. Location data is extracted from area codes for US/Canada numbers.
Call Summaries:
AI-generated summaries of each phone call are saved and visible in your Inbox, including key topics discussed, action items, and sentiment analysis.
7
Missed-Call AI Takeover
Never miss a lead again. When a customer calls your business number, we'll ring your cell phone first. If you don't pick up, the AI agent takes over the call and/or auto-texts the caller — your choice.
Configure it in
Widget Settings → Channels → Phone → Missed-Call AI Takeover
:
Forward to your cell:
Enter the phone number we should ring first (yours, a salesperson's, etc.)
Ring timeout:
How many seconds to ring before falling back (default 20s). Voicemail counts as no-answer, so the AI/SMS still triggers if the call goes to voicemail.
AI callback fallback:
If you don't answer, the AI agent picks up and handles the call
SMS fallback:
If you don't answer, the caller automatically gets a text from your business number with a custom message (e.g. "Sorry we missed you! Reply here and we'll get right back to you.")
Both fallbacks are independent — turn on one, the other, or both. The auto-reply SMS opens a real conversation in your Inbox, so the caller can text you back and the AI can keep helping.
Tip:
The forwarding number is normalized to E.164 automatically (US numbers default to +1 if no country code is given). Use the full international format for non-US numbers (e.g. +447911123456).
8
Common Questions
Can I assign unique DIDs to different agents in one widget?
No. Each widget connects to one AI agent. To have multiple agents with unique phone numbers, create separate widgets and assign each one its own Twilio number.
Can callers be transferred to another AI agent?
Yes! Configure a DTMF transfer destination to dial another widget's Twilio number. When transferred, the new widget's AI agent answers.
What's the difference between 100% AI and hybrid mode?
100% AI: The AI handles the entire call. Hybrid: The AI answers, but callers can press digits to transfer to humans or trigger specific AI responses.

Enable other AI systems to communicate directly with your agents using Google's Agent-to-Agent (A2A) protocol. This allows for AI-to-AI interactions and integration with external AI systems.
1
What is A2A Protocol?
Agent-to-Agent (A2A) is Google's open protocol that enables different AI systems to communicate with each other. With A2A enabled on your agent:
Other AI assistants can discover and message your agent
External systems can integrate your agent into their workflows
Developers can build custom integrations using standard APIs
Your agent becomes part of a larger AI ecosystem
2
A2A Endpoints
Each agent has two A2A endpoints available in the Channels tab:
Discovery URL:
Returns agent metadata in JSON format. Other AI systems use this to learn about your agent's capabilities.
https://yourdomain.com/a2a/widgets/[widgetId]/agent.json
Message Endpoint:
Send messages to your agent via JSON-RPC. Returns AI responses in structured format.
https://yourdomain.com/a2a/widgets/[widgetId]
3
API Usage Example
Send a message to your agent using cURL:
curl -X POST "https://yourdomain.com/a2a/widgets/[widgetId]" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_GOOGLE_AI_API_KEY" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tasks/send",
    "params": {
      "message": {
        "role": "user",
        "parts": [{ "type": "text", "text": "Hello!" }]
      }
    }
  }'

. When a customer replies, the AI evaluates whether the current task's completion condition is met. If yes, it moves to the next task seamlessly. If not, it continues the conversation to work toward completing the current task.
Conversation Flow
Here's what a typical AI Tasks conversation looks like:
AI (Task 1):
"Hi there! Just checking in — are you all OK?"
Customer:
"Yes I'm great!"
AI (Task 2):
"Glad to hear it! Would you like to upgrade your plan?"
"Yes I do"
All tasks complete — flow continues to the next node
Notice the AI transitions between tasks smoothly. When task 1 completes, the AI moves directly to task 2 in a single response — no awkward double messages or repeated questions.
Follow-Up Settings
If a customer stops responding mid-conversation, the AI can automatically follow up to re-engage them.
Enable Follow-Ups:
Turn on automatic follow-up messages for unresponsive customers
Follow-Up Delay:
How long to wait before sending a follow-up (in seconds). Default is 15 seconds for testing; use longer delays in production
Max Follow-Ups:
Maximum number of follow-up attempts before giving up (1-10). Default is 3
Follow-Up Instructions:
Custom instructions for the AI when writing follow-ups. Example: "Gently remind them to respond" or "Aggressively remind them to complete the responses needed"
When the maximum follow-ups are reached without a response, the flow exits through the
"Max Nudges"
output handle so you can handle unresponsive contacts differently.
Meta 24-Hour Window Protection
For Messenger, Instagram, and WhatsApp channels, Meta requires that outbound messages be sent within 24 hours of the customer's last message. AI Tasks automatically detects when this window is about to expire and stops sending follow-ups. If the window closes before all tasks are done, the flow exits through the "Max Nudges" handle — so your fallback path handles it gracefully. You never have to worry about violating Meta's messaging policies.
Output Handles (Branching)
The AI Tasks node has two special output handles that let you branch your flow based on the outcome:
All Tasks Complete (ai-tasks-complete):
The flow follows this path when the customer successfully completes every task. Connect this to the next step in your flow — for example, a confirmation message or a data-saving action.
Max Nudges Reached (ai-tasks-maxnudges):
The flow follows this path when the customer fails to respond after all follow-up attempts. Connect this to a fallback — for example, a "We'll try again later" message or assigning the contact to a human agent.
Important
Always connect both output handles. If a customer doesn't respond and you haven't connected the "Max Nudges" handle, the flow will simply end without any final message.
Tips for Great AI Tasks
Be specific with instructions:
Instead of "Ask about their problem," write "Ask the customer to describe their issue in detail, including when it started and what they've already tried."
Write clear completion conditions:
The AI needs to know exactly when a task is done. "Customer says yes" is better than "Customer responds."
Keep tasks focused:
Each task should have one clear goal. Split complex objectives into multiple smaller tasks.
Order tasks logically:
Put tasks in the order that makes sense for the conversation. Start with greetings or verification, then move to the main objective.
Use auto-complete sparingly:
Only enable auto-complete for tasks that don't require customer input, like sending a summary or logging data.
Test with the flow preview:
Use the built-in flow tester to run through the conversation and verify the AI handles each task correctly.

Channel Messaging Rules
Different messaging platforms have rules about when you can message users. Understanding these helps you design effective automations.
Facebook Messenger — 24-Hour Rule:
You can only send messages within 24 hours of the user's last interaction. After that, you need a Message Tag (for specific use cases) or the user must re-engage first. Tip: Use AI Sequences to send messages right when the 24-hour window opens (when user engages), not after it closes.
Instagram DM — 24-Hour Rule:
Similar to Messenger, Instagram only allows messaging within 24 hours of user interaction. Plan your flows to complete within this window.
WhatsApp — 24-Hour Session + Templates:
Free-form messages allowed within 24 hours of user reply. After that, you must use pre-approved Message Templates (which may have costs). Tip: AI Sequences can automatically use WhatsApp Templates when the session window is closed.
Telegram — No Restrictions:
Telegram has no messaging window restrictions. You can send messages anytime after a user starts a conversation with your bot. Ideal for scheduled campaigns.
Web Chat Widget — Session Based:
Messages only work when the user has the widget open. Long delays don't work for web chat since users may close the browser. Use email or push notifications for follow-ups.
Email — No Time Restrictions:
Email has no messaging window. Perfect for long-term nurture sequences, but respect opt-out preferences and avoid spamming.
SMS — Carrier Rules Apply:
SMS has no platform messaging window, but carrier rules and regulations (like TCPA in the US) require explicit consent. Best for time-sensitive updates.

For Scheduled Campaigns:
Use AI Sequences (days/weeks). Each step triggers a Flow, giving you full control over content and channel-specific handling.
For Messenger/Instagram:
Complete conversations within the 24-hour window. Use sequences that trigger when users engage, not after they've gone silent.
For WhatsApp:
Set up approved Message Templates for follow-ups outside the 24-hour window. AI Sequences will use these automatically when needed.

Browser Agent Documentation
Browser Agent lets AI open and control a real web browser in real-time. Powered by secure cloud browser sessions, it enables your AI to browse the web, extract information, fill forms, and conduct research autonomously.
1
What is Browser Agent
Browser Agent gives your AI the ability to open and control a real web browser in real-time. Unlike simple URL fetching or scraping, the AI interacts with pages just like a human would -- clicking buttons, filling forms, scrolling through content, and navigating between pages.
Each browsing session runs in a secure, isolated cloud browser. The AI can see the page, make decisions about what to do next, and extract the information it needs to answer user questions or complete tasks.
2
How to Enable It
Enable Browser Agent in your widget settings:
Open your Widget/Agent editor
Navigate to the
AI
section
Toggle
"Browser Agent"
on
Once enabled, three sub-settings appear:
Private Sessions (ON by default):
Hides the live browser feed from end users. They see a "Browsing in progress..." status instead of the actual browser view. Use this to protect sensitive content and prevent users from seeing intermediate browsing steps.
Allow Login Pages (OFF by default):
When enabled, the AI can navigate to authentication pages such as Google login, Gmail, and other sign-in forms. It is recommended to keep Private Sessions on when using this setting to prevent exposing credentials in the live browser feed.
Max Pages per Session (default 5, range 1-20):
Controls how many pages the AI agent can visit per browsing session. Higher values allow deeper research across more pages but take longer to complete. Lower values are faster but may miss relevant information.
3
Two Browsing Modes in Chat
Browser Agent operates in two modes depending on user input:
Direct Browse:
The AI visits a specific URL provided by the user and extracts content from that page. This mode is triggered when a user mentions a specific website or URL in their message. Example: A user says "Check example.com for pricing" and the AI opens a browser, navigates to that URL, reads the pricing information, and reports back.
Agent Mode:
The AI is given a research task and autonomously decides how to accomplish it. It searches Google for the topic, evaluates the results, picks the most relevant pages, visits multiple sites, and compiles its findings into a comprehensive response. Example: A user asks "Research the top project management tools and compare their pricing" and the AI searches, visits multiple product pages, and compiles a comparison.
4
What the End User Sees
The user experience depends on the Private Sessions setting:
Public Mode (Private Sessions OFF):
A "Live Browser" panel appears in the chat interface with an expandable iframe showing the real browser session. Users can watch the AI browse in real-time and also open the live browser view in a new tab for a larger view.
Private Mode (Private Sessions ON):
A "Browsing in progress..." status bar with a green dot indicator is displayed. No browser feed or share link is shown to the user. The AI still browses and extracts information, but the session is completely hidden from the end user.
5
Flow Builder Integration

Browse Mode:
Opens a browser at a specific URL and performs a task on that page. Available fields: URL to Browse, Task/Instructions, Save Page Content To (custom field), Save Live View URL To (custom field), View Duration (5-120 seconds).
Autonomous web research where the AI decides which sites to visit. Available fields: Task/Goal, Save Page Content To (custom field), Save Live View URL To (custom field), View Duration (5-120 seconds).
Template variables work in both URL and task fields. For example, use
{{company_name}}
to dynamically insert contact data into browse instructions.
6
Autonomous Form Filling
Browser Agent can autonomously fill out forms, click buttons, and submit data on any website — all from a simple natural language instruction. No technical setup or CSS selectors required. Just describe what you want done in plain English and the AI handles the rest.
How It Works:
The AI navigates to the target page, scans for interactive elements (input fields, dropdowns, checkboxes, buttons), fills in each field with appropriate data from your instructions, then clicks submit and captures the result.
Automatic Detection:
The AI automatically detects when a task requires page interaction. Action words like fill, submit, click, sign up, register, log in, enter, type, book, schedule, apply, checkout, purchase, subscribe, or select trigger autonomous mode.
Built-in Safety:
The system includes intelligent loop detection that prevents the AI from getting stuck repeating the same action. If it detects a repeated interaction on the same element, it automatically moves on.

AI Reply Delay
----------------------------------------

Add a configurable delay before your AI agent responds. This makes conversations feel more natural and human-like, and intelligently combines multiple messages sent during the delay window into a single, cohesive response.
1
What Is AI Reply Delay?
By default, your AI agent responds instantly to every message. AI Reply Delay adds a short pause (0–30 seconds) before the AI generates its response. This serves two purposes:
More human-like pacing:
Instant AI replies can feel robotic. A small delay makes the conversation feel more natural.
Message aggregation:
If a user sends multiple messages in quick succession (e.g., "Hi", "I have a question", "about billing"), the delay window collects them all and the AI generates one thoughtful response addressing everything together.
2
How to Set It Up
Follow these steps to configure AI Reply Delay:
Open your agent in the dashboard
Go to the
Settings
tab
Scroll down and expand
"AI Reply Delay"
Choose your
Delay Mode
(Fixed or Random)
Set the
delay duration
in seconds (0 = no delay)
Click
Save
— the delay takes effect immediately
3
Delay Modes
Choose the delay mode that best fits your use case:
Fixed:
The AI waits exactly the number of seconds you specify (0–30) before responding. Predictable and consistent.
Random (5–30s):
The AI waits a random amount of time between 5 and 30 seconds. This creates a more human-like, unpredictable pacing.
4
Message Aggregation
When a delay is active, users can continue sending messages. The send button stays enabled during the delay window. Here's what happens:
User sends a message — the delay timer starts
User sends another message before the timer expires — the timer
resets
This continues until the user stops sending messages
Once the timer expires, all messages sent during the window are
combined
The AI generates a
single response
that addresses all the messages together
Example:
A user sends "Hi", then "I need help with my subscription", then "it's not renewing". Instead of three separate AI responses, the delay combines them and the AI gives one complete response about the subscription renewal issue.
5
Best Practices
Tips for getting the most out of AI Reply Delay:
Start with 5–10 seconds:
This is a good balance between feeling human-like and not keeping users waiting too long.
Use Random mode for customer support:
Variable timing feels less robotic, which helps when you want the agent to feel more like a real person.
Use Fixed mode for quick bots:
If your agent handles simple FAQ-style queries, a short fixed delay (3–5s) adds just enough pause without frustrating users.
Set to 0 for instant responses:
If speed is your priority (e.g., lead capture bots), keep the delay at zero.
Things to Know
The maximum delay is
30 seconds
.
Setting the delay to
0
disables it entirely (instant responses).
The delay applies to all channels where the agent is active (webchat, WhatsApp, Messenger, etc.).
The typing indicator will appear during the delay so users know the agent is "thinking".
The delay does not affect human agent responses — only AI-generated replies.

When an automation triggers a flow (e.g., "Custom Field Updated" starts a flow), the system automatically detects which channel the contact most recently used and delivers messages on that same channel.
For example: if a contact messaged you on Messenger and their interaction triggered a "Custom Field Updated" automation, the triggered flow's messages will be sent back to them on Messenger — not just to the web chat widget.
Omni-channel Send Message nodes
automatically deliver to the contact's most recent channel (Messenger, SMS, Instagram, Telegram, etc.)
Specific channel Send Message nodes
(e.g., set to "SMS" or "Messenger") force delivery to that channel regardless of how the automation was triggered
If a contact doesn't have an identifier for the target channel (e.g., no phone number for SMS), the message is skipped and the flow continues
To guarantee delivery on a specific channel, set the Send Message node's channel to the desired platform (e.g., "Messenger" or "SMS") instead of leaving it on "Omni-channel". This is useful when you always want to reach contacts via a particular channel regardless of where they originally interacted.

Incoming Webhooks: Connect Any External Service to Your AI Flows
Incoming Webhooks let you trigger automated flows from any external service — no coding required. Every flow gets its own unique webhook URL that accepts data from platforms like Make.com, Zapier, n8n, Tally, Shopify, Stripe, or any app that can send HTTP requests.
What is a Webhook?
A webhook is a URL that listens for incoming data. When an external service sends a POST request to your webhook URL, it triggers your flow automatically with that data. Think of it as a "doorbell" — when someone rings it (sends data), your flow wakes up and runs.
1
How It Works
The flow of data follows these steps:
Enable Webhook
— Open your flow in the Flow Builder, click the Webhook button in the toolbar, and toggle it ON. A unique URL is generated.
External Event
— Something happens in an external service (e.g., new order in Shopify, form submitted, payment received in Stripe).
Webhook Call
— The external service sends a POST request with JSON data to your webhook URL.
Contact Resolution
— We find an existing contact by email, phone, or ID — or create a new one automatically.
Data Stored
— All incoming data is saved to the contact's custom fields, prefixed with
webhook_
.
Flow Runs
— Your flow executes with all webhook data available as template variables like
{{webhook_data.field_name}}
2
Enable Webhook in Your Flow
Set up webhook triggering in a few clicks:
Open your flow in the Flow Builder
Click the
Webhook
button in the top toolbar (looks like a link icon)
Toggle
to ON
A unique webhook URL is generated — copy it
The URL format is:
https://yourdomain.com/api/webhooks/flow/FLOW_ID/SECRET
White-Label Domains
If you're using a white-label custom domain, your webhook URLs will automatically use that domain instead of
your custom domain
. This means your integrations will point to your branded domain.
3
Payload Format
Send a JSON POST request to your webhook URL. Here's the full format:
{
  "contactEmail": "customer@example.com",

  "data": {
    "order_id": "ORD-12345",

    "product": "Premium Plan",
    "custom_field": "any value you want"
  },
  "channel": "webchat"
}

(Optional) — Any custom key-value pairs you want available in the flow

(Optional) — Channel for messages: webchat, sms, whatsapp, telegram, etc. Defaults to "webchat"

Monetize your widgets by selling monthly subscriptions to your clients. Here's everything you need to know about the relationship between client subscriptions and widget access.
1
The Complete Flow - How Everything Connects
Step-by-Step Process:
Create Client Subscription:
Your client (e.g., danny@example.com) pays you $10/month (shown in Subs tab)
Generate License Token:
Platform automatically creates a unique license token for their subscription
Provide Widget Script:
You give them an embed script with their unique license token included
Widget Validates:
When the widget loads, it automatically checks if their subscription is active
Access Granted:
If subscription is active and paid, widget works with unlimited access
Key Point:
All validation happens automatically server-side. The platform verifies payment status with Stripe every time the widget loads, ensuring only paid customers have access.
2

There are two types of widget embed scripts — one public and one for paying clients:
Public Widget (No Subscription Required):
<script src="https://yourdomain.com/widget.js"
    data-widget="80225996" async></script>
Anyone can use this — has demo message limits (typically 5-10 messages)
Paid Client Widget (Subscription Required):
<script src="https://yourdomain.com/widget.js"
    data-widget="80225996"
    data-license="79cd009d-46ff-490c-9356..." async></script>
This token links to their $10/month subscription — unlimited access with no message limits
3
What to Provide Your Paying Clients
You have two options for giving clients access:
Option 1: Embed Script (Most Common)
Give clients this script to add to their website (before closing </body> tag):
<script src="https://yourdomain.com/widget.js"
    data-widget="YOUR_WIDGET_ID"
    data-license="CLIENT_LICENSE_TOKEN" async></script>
Option 2: Direct Widget Link
Or provide a direct link they can share or embed in iframe:
https://yourdomain.com/widgets/YOUR_WIDGET_ID/licensed?token=CLIENT_LICENSE_TOKEN
This link opens the widget directly in a full page with automatic license validation.
For Each Paying Client:
They pay you $10/month (or your set price) via Stripe checkout
You get their license token from the "License" column in Subs tab
The token is automatically included when you copy using the Copy buttons
You send them either the script OR the direct link
They use it and the widget validates their active subscription automatically

Both Script and Direct Link:

Email Tracking & Statistics
Track email opens, link clicks, and campaign performance with detailed analytics.
1
How Email Tracking Works
Our tracking system automatically monitors email engagement:
📬 Open Tracking
A tiny, invisible 1×1 pixel image is embedded in every email. When a recipient opens the email and loads images, the tracking pixel records the open event, timestamp, and how many times they've opened it.
🔗 Click Tracking
All links in your email are automatically wrapped with tracking URLs. When someone clicks a link, we record the click, which link was clicked, and then immediately redirect them to the actual destination. This happens in milliseconds so recipients don't notice any delay.
2
Why Open Tracking Shows Lower Numbers (5-Second Threshold)
You may notice that your
click tracking is accurate
, but
open rates seem lower than expected
. This is intentional and actually protects the accuracy of your analytics.
The Problem: Email Client Bots
Modern email clients like
Gmail, Apple Mail, and Outlook
automatically load tracking pixels
before anyone actually opens the email
. This happens in 1-3 seconds and is done by automated systems for:
Apple Mail Privacy Protection
— Preloads all images through a proxy
Gmail Image Proxy
— Caches images for security scanning
Outlook Safe Links
— Pre-scans content for malware
Corporate Email Security
— Scans emails before delivery
Without our 5-second filter, you'd see 100% open rates within seconds of sending - but those aren't real people!
Our Solution: Smart Open Detection
We use two methods to ensure only
real human opens
are counted:
Method 1: Time-Based Detection
— Opens that happen >5 seconds after sending are counted immediately (likely real human)
Method 2: Click Confirmation
— If someone clicks a link in the email, they definitely opened it - we count it as opened even if the initial pixel load was fast
What This Means for Your Analytics
Click rates are 100% accurate
— Bots don't click links, only real people do
Open rates show real engagement
— No inflated numbers from automated systems
Your data is trustworthy
— Make business decisions with confidence
Industry-standard practice
— Major platforms like Mailchimp struggle with this too
Bottom Line:
If your customer says "opens are showing when emails haven't been opened yet" - that's exactly what we prevent! Our 5-second threshold ensures you only see
, not automated email client activity.
3
Understanding Campaign Statistics
Key metrics to track for your email campaigns:
📊 Open Rate
Percentage of recipients who opened your email
Open Rate = (Unique Opens ÷ Total Sent) × 100
Industry Average:
15-25% (higher is better)
🖱️ Click Rate
Percentage of recipients who clicked any link
Click Rate = (Unique Clicks ÷ Total Sent) × 100
2-5% (higher is better)
📈 Click-to-Open Rate
Percentage of openers who also clicked
CTOR = (Unique Clicks ÷ Unique Opens) × 100
10-15% (measures content effectiveness)
4
Viewing Analytics
Access detailed analytics for each campaign:
Go to Email Marketing in your dashboard
Find your campaign and click the "View Details" action button
View the summary stats showing opens and clicks percentages
Click "Opens" to see a table of everyone who opened the email with timestamps
Click "Clicks" to see which links were clicked and by whom
Export data as CSV for further analysis in Excel or Google Sheets
5
Reading the Analytics Tables
Understanding the data in your analytics tables:
Opens Table Shows:
Name & Email:
Who opened the email
Opens:
Number of times they opened it (shows engagement level)
Opened At:
When they first opened the email
Clicks Table Shows:
Link URL:
The actual link that was clicked
Clicks:
Total number of clicks on that link
People:
Number of unique people who clicked
Who clicked the link
Clicked At:
When they clicked (helps identify hot leads)
Using Analytics to Improve
Low open rates?
Try different subject lines - make them shorter, more personal, or more intriguing
High opens but low clicks?
Your content needs stronger calls-to-action or more compelling offers
Multiple opens from same person?
They're very interested - follow up personally
Quick clicks after open?
Your email is effective and engaging
No engagement?
Try sending at different times or days of the week
Tracking Limitations
Image blocking:
Some email clients block images by default, preventing open tracking
Privacy features:
Apple Mail Privacy Protection may preload images, inflating open rates
Click privacy:
Some email clients scan links before users click, which may register false clicks
Best practice:
Use tracking data for trends and patterns, not individual user behavior decisions

📦 Product Catalog
AI answers questions about inventory, pricing, and availability

Look up customer info, update records, track interactions

How to Set Up
Create a Function:
Go to Functions and create a new function (e.g., "Manage Appointments")

Lookup Column (How AI Finds Rows)
The lookup column is how the AI identifies which row to read, update, or delete. You have two options:
Option 1: AI Auto-Detect  (Recommended)
Select "AI Auto-Detect" from the dropdown and the AI will automatically determine which column to search based on the value provided:
•
Email addresses
→ Searches Email column
Phone numbers
→ Searches Phone column
Dates
(Dec 4, 2025, Thursday) → Searches Date column
Numbers
(12345) → Searches ID column
UUIDs
→ Searches ID/UUID column
Names
→ Searches Name column
Option 2: Fixed Column
Select a specific column from the dropdown. The AI will always search that column. Best when you have a unique identifier like Order ID or Customer ID.
Column Configuration Modes
For each writable column, you can control how the AI determines what value to use:
AI Determines:
The AI decides the value based on conversation context
Choice List:
AI picks from a predefined list (e.g., Status: "Pending", "Confirmed", "Cancelled")
🔒 Fixed Value:
Always use a specific value (e.g., Source: "Website Chat")
AI with Default:
AI determines but falls back to a default if unsure
Delete Safety Features
Deleting data is protected by multiple safety measures:
Confirmation Required:
AI must confirm with the user before deleting
Unique Match Required:
Only deletes when exactly one row matches
Composite Matching:
If multiple rows match (e.g., 2 people named "Ryan"), the AI uses additional columns to find the unique row
Explicit Permission:
You must enable "Allow Delete" in function settings
Example:
If user says "Delete Ryan's appointment from December 4th" and there are 2 Ryans, the AI will use both Name AND Date to find the unique matching row.

Allowlist & Access Control
----------------------------------------

Control who can access your AI agent by restricting it to approved email addresses and domains. You can manage your allowlist manually or sync it from a Google Sheet for bulk management.
Quick Overview
When the allowlist is enabled, only users whose email address (or email domain) appears on the list can interact with your agent. Everyone else sees an "access denied" message. You can add entries manually, or link a Google Sheet to sync them in bulk.
1
Enable the Allowlist
Turn on access restrictions for your agent:
Open your agent in the editor
Go to the
Security
tab
Enable the
Email Verification
or
PIN Verification
option
Navigate to the
Allowlist
section within Security
2
Add Entries Manually
Add individual email addresses or entire domains:
Email Address:
Grants access to one specific person (e.g.,
john@company.com
)
Domain:
Grants access to everyone with that email domain (e.g.,
company.com
allows all @company.com addresses)
You can add optional notes to each entry for your own reference
3
Google Sheets Sync (Bulk Management)
For managing larger lists, you can link a Google Sheet:
In the Allowlist section, find the
Google Sheets Source
card
Click
"Create or Select a Google Sheet"
Create New:
Auto-creates a sheet named "Allowlist - [Agent Name]" with an "Email" column header ready to go
Select Existing:
Pick any spreadsheet from your Google Drive
Choose the
and
column
that contains your emails/domains
Connect Sheet
to link it
4
Automatic Syncing
Once a sheet is connected, entries sync automatically:
Entries are synced
immediately
when you first connect the sheet
After that, the system
auto-syncs every 5 minutes
— no action needed
New entries in the sheet are added to the allowlist automatically
Entries removed from the sheet are removed from the allowlist automatically
Entries you added manually are never touched during sync
The system auto-detects whether each value is an email or a domain
You can still click
Sync Now
at any time if you want an immediate update
How Sync Works
The sync process distinguishes between entries you added manually and entries imported from Google Sheets. Sheet-synced entries are internally tagged so the system knows which ones to manage during sync.
Sync Behavior
Adding:
Any email/domain in the sheet that isn't already in the allowlist gets added automatically
Removing:
If you remove a row from the sheet and sync again, that entry is removed from the allowlist
Manual entries preserved:
Entries you added by hand (not from the sheet) are never affected by sync
Duplicate prevention:
If an entry exists both manually and in the sheet, it won't be duplicated
Auto-classification:
Values containing @ are treated as emails; everything else is treated as a domain
Access Logs & Blocking
The allowlist page also shows recent access attempts and lets you block specific users:
Recent Access:
See who has accessed your agent, when, and from what IP address
Block:
Click the block icon next to any access log entry to permanently prevent that user from accessing the agent
Unblock:
Remove any blocked user from the blocked list to restore their access
Clear Logs:
Remove all access log history with one click
Tips & Best Practices
Use domain entries (e.g.,
) to grant access to an entire organization without listing every email
Keep a master spreadsheet with all approved emails and use Google Sheets sync for easy bulk updates
Manual entries are great for one-off additions that you don't want to manage in a spreadsheet
Sync runs automatically every 5 minutes, so new entries in your sheet are picked up without any action from you
You can also click "Sync Now" at any time for an immediate update
The allowlist takes priority over other access restrictions

Keywords Documentation
Create keyword triggers that intercept incoming messages BEFORE AI processing. When a user sends a message containing your keyword, it immediately responds with your configured text or triggers a flow - completely bypassing the AI.
1
What Are Keywords?
Keywords are trigger words that intercept messages before they reach your AI agent. When matched:
Instant Response:
Your keyword response is returned immediately without any AI processing
Cross-Channel:
Works on webchat, WhatsApp, Messenger, Telegram, Discord, and SMS
All AI Providers:
Works with OpenAI, Claude, Gemini, and Grok
Case-Insensitive:
"HELP", "Help", and "help" all match the same keyword
2
How to Create Keywords
Follow these steps to set up keyword triggers:
Go to
Tools → Keywords
in your dashboard
Click
"Add Keyword"
to create a new trigger
Type your trigger words and press
Enter
to add each one (you can add multiple keywords to the same trigger)
Select
"All Agents"
or choose a specific agent
Choose your response type:
Text Response:
Enter exact text to send back
Trigger Flow:
Select a flow to start (filters to selected agent's flows)
"Create Keyword"
to save
3
Common Use Cases
Here are popular ways to use keywords:
🆘 Support Shortcuts:
"help" → Triggers support flow or shows menu of options
🛑 Opt-Out Handling:
"stop", "unsubscribe" → Runs opt-out flow
💰 Pricing Info:
"pricing", "cost" → Returns your pricing details
👋 Quick Greetings:
"hi", "hello" → Starts welcome flow
📞 Contact Info:
"contact", "phone" → Returns contact details
🔄 Reset Conversation:
"restart", "new" → Clears history and starts fresh
4
How Matching Works
Understanding keyword matching behavior:
Word Boundary Matching:
Keywords match as complete words, so "help" matches "help me" but not "helpful"
"STOP", "Stop", and "stop" all match the same keyword
Priority:
Agent-specific keywords take priority over "All Agents" keywords
First Match Wins:
If multiple keywords could match, the first active one is used
Intercepts Before AI:
Keyword detection happens BEFORE the message reaches your AI agent
5
Technical Details
For developers and advanced users:
Detection Point:
Keywords are checked after pause/block checks but BEFORE AI processing
All LLM Endpoints:
OpenAI (V3), Claude, Gemini, and Grok endpoints all support keywords
Response Format:
Text keywords return the response directly; flow keywords trigger the flow and return empty content
No AI Tokens Used:
Keyword responses don't consume any AI tokens since they bypass the LLM entirely
Best Practices
Use short, common words that users naturally type (help, stop, menu, pricing)
Add multiple variations to the same trigger (e.g., "stop", "unsubscribe", "opt out")
Test your keywords across different channels to ensure consistent behavior
Use flows for complex responses that need multiple steps or data collection
Review keyword analytics to see which triggers are most used

Widget FAQ & Common Questions
Answers to frequently asked questions about widget behavior, security, and troubleshooting common issues.
1
Spam & Security Protection
How do I protect my widget from spam or bot attacks?
Your widget includes built-in protection against spam and abuse:
Rate Limiting:
Visitors are limited to 30 messages per minute per IP address. Exceeding this limit returns a "Too many requests" error and temporarily blocks further messages.
Sequential Processing:
Messages are processed one at a time per conversation to prevent flooding and ensure proper response order.
Automatic Timeout:
Long-running requests are automatically terminated after 30 seconds to prevent abuse.
What happens when someone exceeds the rate limit?
When a visitor sends more than 30 messages in a minute, they'll see a "Too many requests - please wait before making another request" message. The limit resets after one minute. This prevents both automated bots and manual spammers from overwhelming your chatbot.
Can I customize the rate limit for my widget?
Yes! You can customize the rate limit directly in your Widget Settings under the Security section. Use the slider to set anywhere from 5 to 100 messages per minute. Lower values provide stronger spam protection, while higher values are better for high-traffic legitimate use cases. The default of 30 works well for most scenarios.
2
Message Handling
Can the chatbot wait and respond to multiple messages at once?
By default, the chatbot responds to each message individually as it arrives. However, you can achieve consolidated responses using the
Flow Builder
:
Create a multi-step flow that collects all needed information (name, email, question, etc.) before triggering the AI response
Use "User Input" steps to gather data sequentially
Only trigger the AI response after all inputs are collected
This approach gives you full control over when the AI responds and ensures all context is available.
Why do I see duplicate messages or responses?
This is rare but can happen if a visitor rapidly sends the same message multiple times before the first one finishes processing. Our message queue system prevents race conditions and processes messages in order, but extremely rapid clicking might occasionally cause this. The rate limiting helps prevent this behavior.
Messages are being processed slowly - what can I do?
Response time depends on several factors: AI model complexity, knowledge base size, and any external integrations (APIs, Google Sheets, etc.). To speed things up:
Use a faster AI model in Widget Settings
Optimize your system prompt (shorter is often faster)
Reduce the number of active integrations if not needed
3
Common Widget Issues
Widget not appearing on my website
Check these common causes:
Script not added:
Make sure you've copied the embed code to your website's HTML, ideally before the closing </body> tag
Widget disabled:
Check that the widget is enabled in your dashboard
Cache issues:
Clear your browser cache or try in incognito mode
Script blockers:
Ad blockers or privacy extensions might be blocking the widget script
AI is not responding or gives generic answers
Try these solutions:
Check your system prompt:
Make sure it's clear and provides good context for the AI
Add knowledge:
Upload documents or crawl your website to give the AI accurate information
Verify API keys:
If using your own AI keys, make sure they're valid and have remaining credits
Test prompts:
Test your prompts before deploying to ensure quality responses
Customizations not showing up
After making changes to widget appearance or behavior, you may need to:
Wait a few seconds for changes to propagate
Hard refresh your website (Ctrl+Shift+R or Cmd+Shift+R)
Clear browser cache if using aggressive caching
Conversation history not showing
Conversation history is stored in the browser's local storage by default. History won't persist if:
The visitor uses private/incognito browsing
The visitor clears their browser data
They access from a different device or browser
To enable persistent history across devices, use the contact identification feature to link conversations to user accounts.
4
Best Practices
How should I handle abusive or offensive users?
You have several options:
System prompt:
Instruct your AI to politely decline inappropriate requests and redirect to support
Transfer to human:
Set up automatic handoff to live agents when conversations become difficult
Rate limiting:
Built-in rate limits prevent rapid message spam
Monitor inbox:
Review conversations regularly to identify problematic patterns
How can I collect user information before starting the chat?
Use the
Pre-Chat Form
feature in Widget Settings → Behavior. You can require visitors to enter their name, email, phone, or custom fields before the conversation starts. This information is automatically saved to the contact record.
What's the best way to test my widget before going live?
Use the built-in preview in the widget editor - it shows exactly how your widget will appear and behave. Test different scenarios, edge cases, and make sure your AI handles common questions correctly before deploying.

HTTP Error Codes Reference
Understanding what went wrong when you see an error code. This guide explains common HTTP status codes in plain English.
1
2xx - Success Codes
These codes mean everything worked correctly:
200 OK:
Everything worked perfectly. Your request was successful.
201 Created:
Success! A new resource was created (like a new contact or campaign).
204 No Content:
Request succeeded, but there's no data to send back (often used for deletions).
2
4xx - Client Error Codes (Something You Need to Fix)
These errors indicate an issue with the request you sent:
400 Bad Request:
You sent incomplete or invalid data.
Example: Submitting a form with a missing required field, or sending text where a number is expected.
401 Unauthorized:
You're not logged in or your session expired.
Solution: Log in again or refresh your authentication.
403 Forbidden:
You're logged in but don't have permission to access this resource.
Example: Trying to delete someone else's campaign or access admin-only features.
404 Not Found:
The thing you're looking for doesn't exist.
Example: Trying to view a deleted campaign, or a page that never existed.
408 Request Timeout:
Your request took too long to send.
Usually caused by slow internet. Try again with a better connection.
409 Conflict:
Your request conflicts with the current state.
Example: Trying to create a contact with an email that already exists.
413 Payload Too Large:
The file or data you're uploading is too big.
Solution: Reduce file size or split your data into smaller chunks.
422 Unprocessable Entity:
Your data is formatted correctly but has validation errors.
Example: Email address is in wrong format, or password doesn't meet requirements.
429 Too Many Requests:
You're sending too many requests. Slow down!
Solution: Wait a few moments before trying again. This protects against abuse.
3
5xx - Server Error Codes (Not Your Fault)
These errors indicate a problem on the server side:
500 Internal Server Error:
Something broke on our server. This is not your fault.
Solution: Try again in a moment. If it persists, contact support.
502 Bad Gateway:
The server got an invalid response from another service it depends on.
Example: Our server tried to connect to a payment processor or email service that sent back garbage data.
503 Service Unavailable:
The server or service is temporarily overloaded or down for maintenance.
Common cause: Email servers getting overwhelmed when sending bulk campaigns. We now handle this automatically by sending emails in the background.
504 Gateway Timeout:
The server waited too long for a response from another service.
Example: Waiting for an external API that never responded. Similar to 503 but specifically about timeouts.
4
General Troubleshooting Tips
Follow these guidelines when encountering errors:
4xx errors:
Check what you're sending. Look for missing fields, invalid formats, or permission issues.
5xx errors:
Wait a moment and try again. If it persists, it's likely a server issue that needs fixing.
Network errors:
Check your internet connection. Sometimes the error isn't from the server at all.
Save your work:
Before submitting large forms or uploads, copy important text to avoid losing it if an error occurs.
Error messages:
Read them carefully - they often tell you exactly what's wrong and how to fix it.
